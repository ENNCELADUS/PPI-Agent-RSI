Research status

Can an LLM scientific agent that combines a DL predictor with biological evidence learn from sparse experimental feedback, and does it gain more from the same labels than the DL predictor retrained on them? This page gives the task, the current design and the current results (status of 2026-11-24). Full results: classification-test summary.

1. Task

Let \(V\) be a set of proteins. An unordered pair \(e = \{u, v\}\), \(u \ne v\), has a label \(y(e) \in \{0, 1\}\), with \(y(e) = 1\) if the proteins interact. Four disjoint sets of pairs make the splits:

  • Training set \(\mathcal{K}\): labelled pairs. They train the DL predictor \(f_\theta(e) \in [0, 1]\), and the agent can look them up. All labels are visible from the start.
  • Validation set \(\mathcal{D}_{\text{va}}\): for selection only (DL hyperparameters and epoch, and the gate of each round). Its labels never reach the agent, and no round can reveal them.
  • Development set \(\mathcal{D}_{\text{dev}}\): pairs whose labels are hidden until a round reveals them. The label budget is much smaller than this set, so the choice of the pairs can matter. These labels are the only feedback for the improvement of the system.
  • Final test split \(\mathcal{D}_{\text{fin}}\): fixed before any run, hidden during all rounds and scored once, after the last round.

Rounds

The system state \(S_t\) holds the parts that can change: the agent's case memory, its lessons and the predictor parameters \(\theta\). The LLM weights, prompts and tools do not change. \(S_0\) depends only on \(\mathcal{K}\) (empty memory, predictor trained on \(\mathcal{K}\)). In each round \(t = 1, \dots, T\):

  1. Batch. A batch \(B_t \subseteq \mathcal{D}_{\text{dev}}\) of \(b\) pairs that are not yet labelled. An acquisition rule chooses them: \(B_t = \pi(S_{t-1}, \mathcal{D}_{\text{dev}})\). The rule can be a random draw (the control: the same batches for every arm), a rule on the predictor scores, or the agent's own picks.
  2. Predict. The system gives \(\hat p(e \mid S_{t-1})\) for each \(e \in B_t\), before the reveal.
  3. Reveal. The oracle returns \(y(e)\) for each \(e \in B_t\). This simulates a wet-lab assay.
  4. Update. \(S'_t = U\big(S_{t-1},\ \{(e, y(e)) : e \in B_t\}\big)\): new cases, revised lessons and a retrained predictor.
  5. Gate. The round is kept only if it improves the validation score \(g\) (AUPRC on \(\mathcal{D}_{\text{va}}\)) over every earlier kept state; otherwise the system goes back to the last kept state.

\[ S_t = \begin{cases} S'_t & \text{if } g(S'_t) > \max_{s < t,\ s \text{ kept}} g(S_s) \\ S_{t-1} & \text{otherwise} \end{cases} \]

The experimental budget is \(bT\) labels. After round \(T\), the state \(S_T\) is frozen.

Objectives

Primary: final test metrics. The frozen system gives \(\hat p(e \mid S_T)\) for each \(e \in \mathcal{D}_{\text{fin}}\). We report AUPRC (main), AUROC and Brier score. The gain from the rounds is the score of \(S_T\) minus the score of \(S_0\) on the same \(\mathcal{D}_{\text{fin}}\). The reference is the DL predictor retrained on the same revealed labels.

Secondary, when the agent picks the batches: hits. When the agent picks the batches, it guides the wet-lab experiments. Then we also measure how many interactions its picks find (Roohani et al., ICLR 2025):

\[ \text{hits}(T) = \Big|\, \{e : y(e) = 1\} \cap \bigcup_{t=1}^{T} B_t \Big| \;\le\; bT . \]

A random pick is a hit with the base rate of \(\mathcal{D}_{\text{dev}}\). Under the random rule the hits only show the base rate, so they are not a metric there.

2. Current design

  • Agent harness. DeepSeek-V4 Pro (thinking high) in the pi runtime. Each batch is one fresh session with a cap on tool calls: protein annotations, protein search, sequence homologs, training-set partners, case retrieval and, in the arms with the predictor, the DL scores of up to 200 pairs per call. The session returns one probability and the evidence IDs for each pair.
  • Memory. Case memory: one record per revealed pair (label, the agent's p, the predictor's p, evidence), written by the system. Lessons: at most 30 active rules, each with supporting and contrary cases, written by a reviewer session with the same LLM. The lessons go in the prompt; the cases come through case retrieval.
  • DL predictor. An ESM-3 motif-graph pair classifier (V3). Checkpoint \(t\) is retrained from scratch on \(\mathcal{K}\) plus the kept rounds; in round \(t\) the agent sees checkpoint \(t-1\).
  • Gate. Every round has a gate on both benchmarks. The DL predictor uses the full validation set. Each agent uses 400 fixed validation pairs (200 positive), scored without memory updates. On a dropped round the revealed pairs stay spent, but their cases and lesson changes leave the memory.
  • Discovery track (PRING, internal). A separate experiment about the acquisition rule: the agent picks 10 × 200 pairs from all 732,655 pairs of the development proteins, and the metric is the hits. A batch with a pair that was already tested or that is listed twice is rejected at submission, and the agent sends it again (in the run of 2026-11-02, before this rule, 105 of 2,000 picks were repeats). It is not part of the update-target comparison, because a random draw from that space reveals almost only negatives (about 28 positives in 2,000).
  • Arms. An arm is an update target (Table 2), a system and an acquisition rule. The update target is the central axis: it says what the revealed labels change. Systems: the DL predictor retrained on the revealed labels; the LLM-only agent; the LLM agent with the DL predictor. The baseline rule on both benchmarks is the random draw from the development set, with a fixed seed and no use of the labels (as in Zeng and Luo, 2026). Under it every arm gets the same 10 batches. The baseline arm is the DL predictor with the random rule. Every arm has the same final test. One run per arm.

3. Current results

The layout follows Zeng and Luo (2026, Does reflective LLM feedback survive a wet-lab-scale label budget?): one row per arm, and an arm is an update target, a system and an acquisition rule. Their controller axis says who edits the predictor; our update target says what the revealed labels change (Table 2). The baseline row is the DL predictor with the random rule, where only the predictor weights change (their "no edits" arm with random acquisition), and the random rule is the baseline rule on both benchmarks. No arm has run on the current split yet; the numbers come from the splits before 2026-11-24 and are kept as separate rows.

Reading (earlier split)

  • The DL predictor gains most from the revealed labels: +0.019 AUPRC (0.716 before the rounds, 0.735 after), against +0.003 and +0.005 for the agents.
  • The agent with the DL predictor stays below the retrained DL predictor alone (0.715 against 0.735) (Table 3).
  • The gate keeps few rounds (1 to 3 of 10), and without it every arm ends lower (Table 3 caption).
  • On PRING the case memory adds +0.028 AUPRC for the agent with the DL predictor (from 0.775) and +0.010 for the LLM-only agent (from 0.801, the matched run of 2026-11-24); the retrained DL predictor gains +0.021 (from 0.695). The lessons add nothing beyond the cases (Table 4). PRING labels are public, so this is not a claim.
  • In the discovery track the agent's picks find interactions far above the base rate: 1,624 of 1,895 valid picks, against about 27 at the base rate of 1.41% (Table 4).
  • Each arm has one run: the numbers are point estimates; the AUPRC of one 100-pair round varies by about ±0.05.

4. Not in the current design

  • Runs on the splits of Table 1: section 3 shows the earlier splits.
  • Acquisition rules on 22T other than the random draw: a rule on the predictor scores (highest score, or score nearest 0.5) and the agent's own picks. The development set is built; these rules are not, so the agent does not yet guide the experiments on private data.
  • The DL predictor arm on PRING with the random rule: it needs one retraining per round on the random batches, with the gate. The agent arms on PRING read the frozen predictor.
  • Improvement of the prompts, tools or predictor architecture: only the memory and the predictor weights change.
  • Replicate runs and a permuted-label control.
